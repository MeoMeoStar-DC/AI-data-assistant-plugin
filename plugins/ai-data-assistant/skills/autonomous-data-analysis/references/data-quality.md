# 面向当前分析的数据质量检查

质量检查围绕会改变当前答案的风险进行，不将通用清单全部转成查询。复用已有结构、事实和 Runtime 信息；缺少参考不是关闭合法只读路径的理由。

## 查询与关联前

- 明确一行代表的业务实体与时间粒度；验证候选关联键的唯一性和关联基数，不仅核对字段同名。
- 区分明细、分组结果和总计。连接前后比较行数、业务键数量、度量总值及未匹配比例；存在放大时先预聚合或修正连接，再解释变化。
- 时间窗口需要完整性证据：已执行区间、来源实际有数日期与迟到/成熟规则分别记录；没有记录的日期不等于零。
- 指标和字段用途来自正式合同或可核实结构。标识符与分类字段检查缺失、唯一性和合法值，不计算均值、极差等无业务意义统计。

## 结果可信范围

缺失、空值和零分别统计，并说明分母与受影响范围。检查使用的样本是全量、抽样、Top N 还是截断结果；分页完整不等于源查询未截断。局部样本不能推断全体异常率或总体分布。

来源冲突时先对齐期间、时区、人群、去重、分子分母、单位和新鲜度，只增加能定位差异的查询。不能平均不等价来源或拼接为一条完整趋势。

需要验证查询时沿用 preview、展示和执行流程，使用 `coverage_mode=validation`；验证证据不替代正式结果义务。已有结果足以检查的问题直接复用，不追加无信息增益的仓库调用。

## 问题处理

报告具体受影响字段/群体/期间、问题大小、可能偏差及最小修复动作。先尝试确定性修复、等价来源或带限制交付。不能修复的质量问题影响哪些结论就限制哪些结论，不因辅助检查失败丢弃其他可信结果。

不自动修改业务数据、正式指标或 Runtime。修复建议与已执行修复分开表述，未经工具核实的原因只能作为待验证解释。
